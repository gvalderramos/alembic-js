# Test resources

Real-world Alembic files used by tests, the sandbox and benchmarks. Small, exact unit-test fixtures live in [`test/fixtures/`](../test/fixtures) and are generated by [`tools/generate_fixtures.cpp`](../tools/generate_fixtures.cpp). The files here exist to cover what real DCC exports actually contain: naming conventions, layouts, and quirks.

Rules (see [spec 0007](../specs/0007-test-assets.md)):
- Every file has a known source and a license that allows redistribution.
- Prefer files we can regenerate from a script in this repo.
- Keep committed files small (a few MB). Large benchmark files are generated or downloaded on demand and are git-ignored.

## Catalog

### `Ancient_Kettle.abc` (3.3 MB)
- **Source:** Blender export (Alembic 1.7.12, 2021). Original author "WT"; source URL and license **unknown — to be confirmed**.
- **Contents:** camera, 3 static meshes (quads, no normals or UVs), and user property `meshtype`.
- **Quirks:** the kettle body has 250 identical samples, so `isConstant()` is true. The archive start and end times are equal (1/24 s).
- **Used by:** `test/three.test.ts`, the sandbox, spec 0006 (user property regression).

### `blender/` — generated by [`tools/blender/make_test_assets.py`](../tools/blender/make_test_assets.py)
- **Source:** created by this project with Blender 5.2.2 LTS, so the license is the same as this repository (MIT).
- **Regenerate:** `yarn assets:blender` (needs `blender` on `PATH`, or `BLENDER=/path/to/blender`). Files are reproducible in content but not byte-for-byte, because the archive stores its write time.
- **Axes:** Blender converts its Z-up scenes to Y-up on export. A Blender position (x, y, z) appears as (x, z, −y).

### Blender export behaviour worth knowing
These came up while building the assets, and readers must handle them:
- **User properties are written as arrays**, even single values (`arraysize=1`). Spec 0006 unwraps them.
- **Only the active color attribute and the active UV map are exported.** Extra UV sets and other color attributes are dropped.
- **Mixing spline types** (poly, Bezier, NURBS) in one curve object writes an empty curve with 0 samples. The script uses one spline type per object.
- **Bezier curves** are exported with their handles as control vertices (3 points become 7 control vertices), but widths stay per original point.
- **Face sets** get names from the materials. A subd object without materials gets one face set named `default`.

## Not covered yet
- **Houdini conventions:** particles with `v`, `id`, `Cd`, `age`; fluid meshes. Needs a Houdini export, or a downloaded sample with a compatible license.
- **Maya conventions:** color sets, `-attr` / `-userAttr` exports, face sets on shapes.
- **AbcMaterial data** (spec 0003): Blender doesn't write it. Generate it with `tools/generate_fixtures.cpp`.
- **Legacy HDF5 archive:** should fail with `ERR_ABC_INVALID_ARCHIVE`. Needs an HDF5-enabled Alembic build to create one.
